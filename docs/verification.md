# Проверка Docker-демо — 26 октября 2026

Среда: Windows, Docker Desktop 4.52.0, Linux Engine 29.0.1. Команда `docker compose -f compose.demo.yaml up --build -d` успешно собрала модель и API, создала отдельный volume `alfahack-demo_demo_data`, запустила PostgreSQL 17, Python/CatBoost и Go с фронтендом. Модель и БД получили статус healthy. Использовалась новая БД демо; учебная БД на 5433 не менялась.

## Результаты

- `go test ./...` и `go vet ./...`: успешно.
- `MODEL_URL=http://127.0.0.1:8001 python scripts/check-model.py`: обе точки входа модели вернули контрольную PD 0.026779217258366402, класс A, 32 признака.
- `python scripts/smoke.py`: успешно. Реальный CatBoost через Go; принятие условий и моделируемая выдача; повторная подача; стоп-фактор до вызова модели; ограничение доступа; согласие и доработка из NEED_INFO; загрузка документа и ручное решение по оборудованию.
- `TEST_DATABASE_URL=... go test -run TestIntegration -v ./...`: успешно на Docker-БД демо. Ошибка модели направляет заявку на ручное рассмотрение; стоп-фактор предотвращает вызов модели.
- `node scripts/browser-check.cjs`: успешно в headless Edge. EXPRESS и EQUIPMENT до выдачи, загрузка документа, ручное изменение рекомендации, подписание, мобильная вёрстка; ошибок JavaScript не обнаружено.

Сквозные проверки создают синтетические заявки и события в базе демо. Это проверка работоспособности прототипа, не доказательство качества кредитного скоринга, безопасности промышленной эксплуатации или нагрузочной устойчивости. Проверка проведена на рабочем компьютере автора с Docker-кэшем, не на независимом компьютере экспертов.
